1. Ringkasan eksekutif

Continuous Assurance (IT) adalah produk Atumcell untuk menjawab celah antara scan otomatis terus-menerus (banyak noise) dan pentest berkala (dalam, tapi cepat kedaluwarsa). Produk memantau attack surface eksternal secara berkelanjutan, memvalidasi temuan penting dengan manusia, dan menutup temuan hanya setelah retest — lengkap dengan sertifikat penutupan bertanggal.

Bukan compliance automation ala Vanta/Drata. Bukan security rating murni ala Bitsight. Ya: continuous external monitoring + human validation + verified closure + portofolio PE + binder asuransi.

Analog terdekat di pasar: Rapid7 Vector Command (continuous recon + human red team). Yang tidak ditiru: Exposure Command Ultimate (CNAPP, agent, ratusan konektor).

2. Masalah & peluang

2.1 Masalah pelanggan

  1. Noise otomatis — alat EASM/scanner menghasilkan banyak temuan tanpa bukti eksploitasi.
  2. Assurance kedaluwarsa — laporan pentest tahunan tidak merefleksikan perubahan attack surface mingguan.
  3. Klaim berlebihan — “sudah dipantau” sering disamakan dengan “sudah aman”, tanpa memisahkan tervalidasi vs belum diperiksa.
  4. Bukti sulit dipakai — auditor, underwriter, dan IC PE butuh artefak bertanggal, bukan screenshot scan.
  5. Sponsor PE buta spot — sulit roll-up risiko lintas portofolio perusahaan.

2.2 Peluang Atumcell

  • Keahlian pentest / red team Atumcell menjadi diferensiator inti (bukan add-on).
  • Posisi mid-market & PE: lebih fokus dari platform CTEM enterprise-heavy.
  • Sinergi potensial dengan AtumScan / AtumScreen / SpoofCheck (keputusan terbuka).

3. Tujuan produk

3.1 Goals

  1. Memberikan assurance yang bisa dibuktikan atas eksposur eksternal.
  2. Memisahkan secara eksplisit: human-validated / automated / unscanned.
  3. Menghubungkan monitoring kontinu dengan siklus pentest Atumcell.
  4. Menghasilkan artefak penutupan (sertifikat) dan laporan untuk auditor, asuransi, PE.
  5. Menyediakan roll-up portofolio untuk sponsor PE + pipeline due diligence.

3.2 Non-goals (v1)

  • Platform compliance penuh (kebijakan, HR, vendor risk ala Vanta).
  • CNAPP / agent endpoint / 500+ cloud connector.
  • Vulnerability management internal penuh (VM agent-based) sebagai fokus utama.
  • Menggantikan seluruh stack XDR/SIEM.

5.1 Diferensiator wajib di produk

  1. Label human-validated eksplisit di setiap temuan.
  2. Sertifikat penutupan bertanggal setelah retest.
  3. Siklus pengujian menyambung monitoring ↔ pentest.
  4. Portofolio PE + due diligence.
  5. Binder asuransi sebagai laporan pembeda.

6. Prinsip produk

  1. Prove, don’t claim — jangan menyamakan scanned dengan secured.
  2. Human in the loop untuk yang penting — critical / KEV / high-impact wajib jalur validasi.
  3. Closure is a verb — tutup hanya lewat verifikasi, bukan drag ke “done”.
  4. Artefak > dashboard — output harus bisa dilampirkan ke pihak ketiga.
  5. Agentless-first (v1) — fokus eksternal; perluasan internal opsional kemudian.
  6. UI jujur — coverage gap (unscanned) ditampilkan terang-terangan.

7. Ruang lingkup

7.1 In scope — MVP / v1

  • Discovery attack surface eksternal (DNS, CT, IP range, cloud bucket publik, related domain).
  • Finding management dengan severity, KEV, SLA, owner.
  • Antrian & kuota human validation + emergent KEV queue.
  • Remediation kanban + verified closure + sertifikat.
  • Testing cycle: usulan scope, kuota, riwayat uji.
  • Evidence readiness sempit (CIS teknis, SOC2 CC teknis, ISO Annex A teknis, asuransi).
  • Reports multi-audiens termasuk insurance binder.
  • PE Portfolio: KPI, daftar perusahaan, matriks, DD pipeline.
  • Multi-tenant company view; tema light/dark.

7.2 Out of scope — v1

  • Agent / EDR / cloud posture penuh (CSPM/CNAPP).
  • Policy library & employee security training.
  • Vendor risk management penuh.
  • Mobile app native.
  • OT / ICS Continuous Assurance (produk terpisah jika ada).

8. Journey pengguna utama

8.1 Assurance cycle (inti)

Discover → Validate → Prioritize → Remediate

  1. Discover — sweep menemukan aset & perubahan surface.
  2. Validate — manusia mengonfirmasi/menolak temuan otomatis; escalate bila perlu.
  3. Prioritize — critical + KEV + dampak bisnis jadi antrian kerja.
  4. Remediate — perbaikan → retest → sertifikat penutupan.

8.2 Journey CISO (mingguan)

  1. Buka Overview: skor, critical aktif, % human-validated.
  2. Review KEV / emergent queue.
  3. Generate laporan board atau binder asuransi.

8.3 Journey engineer

  1. Filter findings pending / critical.
  2. Buka detail → bukti & langkah reproduksi.
  3. Minta validasi atau tandai fixed → request retest.
  4. Gerakkan kartu di Remediation; tutup via verifikasi.

8.4 Journey PE sponsor

  1. Buka PE Portfolio: KPI dana, perusahaan berisiko.
  2. Filter / klik matriks risiko.
  3. Review DD targets & rekomendasi.

12. Aturan bisnis kritis

  1. Temuan tidak boleh berstatus “Closed verified” tanpa retest lulus oleh validator berwenang.
  2. Request human validation mengurangi kuota; retest remediasi tidak mengurangi kuota.
  3. KEV / emergent masuk antrian prioritas dengan SLA terpisah.
  4. UI wajib menampilkan aset unscanned — tidak boleh menyembunyikan coverage gap.
  5. Sertifikat memuat identitas finding, tanggal, validator, dan penanda integritas.
  6. Laporan asuransi hanya menyertakan temuan/penutupan yang memenuhi ambang bukti (configurable).

15. Asumsi, risiko, keputusan terbuka

15.1 Asumsi

  • Tim pentest Atumcell dapat menopang SLA validasi untuk jumlah tenant pilot.
  • Pelanggan menerima model agentless eksternal sebagai titik masuk.
  • Buyer menghargai sertifikat penutupan lebih dari skor generik.

15.2 Risiko

Duplikasi produk Atumcell existingKanibalismeKlarifikasi payung vs produk baru

15.3 Keputusan yang dibutuhkan dari lead

  1. Buyer utama: CISO mid-market, PE, atau keduanya?
  2. Hubungan dengan AtumScan / AtumScreen / SpoofCheck?
  3. Batas v1: eksternal agentless saja, atau ikut internal/VM?
  4. Kedalaman human validation: triage mingguan, continuous red team, atau hybrid (seperti Vector Command Advanced)?
